# The Song Explained — template 1.0

Original 9:16 illustrated music explainers. First episode: Fast Car (1988), 40 seconds, 1080 × 1920, 60 fps. The series uses its own cream/ink/ochre/red/blue vector aesthetic and original Canvas Path2D artwork. It does not imitate album art or use commercial song recordings or lyrics.

## Production

Follow docs/SERIES_WORKFLOW.md. Create one project.json per episode with unique slug, seriesId=the-song-explained, season, episodeNumber, templateVersion=1.0 and productionStatus=review. The manifest discovers it without a catalog edit. The static series cover is separate from individual episode art.

Use layout=doodle-explainer, fullBleed=true, doodle.extras containing song-explainer-v1 and mind-series-v1. The latter is only the existing audio generator selector; the song renderer takes precedence. Set shot:road, room, shop, night, return or symbol; camera:push or pull; symbol:car, record or heart; artist:NAME · YEAR; episode:NN. Headline line breaks use |. Add original story-specific scene presets for new songs rather than blindly reusing Fast Car imagery. Scene fields, camera, narration and covers are editable in Studio. The person rig has stand, look, work, sit, walk and tired poses internally; new scene presets may use these. No external image service or new build dependency.

First scene only: cover-title:FAST CAR and cover-hook:More than a car. The first 0.85s of the video shows the matching Canvas cover. Export it separately through the existing Shorts/TikTok PNG button. Create a static original episode SVG for thumbnailUrl. The studio series SVG is 16:9 and the episode SVG 9:16.

## Audio and export

Existing cached Piper generation produces English voiceover, independent synthetic instrumental score and timing estimates per scene. No changes to the generator or workflow are required. The manifest replaces fallback captions with measured-duration cues (approximate phrase timing, not word alignment). The cover stays unobstructed until 0.85s. The project includes fallback timed captions for local builds without generated audio. Use existing audio track controls to remove the score for voice-only export or remove both tracks for a caption-only version; these are not three separate pre-rendered files. Audio edits require normal GitHub publication to regenerate narration. The score is independent of the song and must not reproduce its melody. Render from Studio with the standard browser MP4 export, not the manual server-master workflow.

## 2.1 — hero face and vehicle polish (TSE-09A–E)

Fast Car keeps the five existing beats, 40 seconds, captions and audio tracks. The extra marker song-hero-rigs-v21 opts into the new modules. Versions 1.0 and 2.0 retain their original rendering.

- songHeroFace.ts: three hand-authored vector facial angles, consistent character features, sculpted cheek/neck shadows, hair highlights, eyes with lids/irises, and expression-specific blink, gaze and head tilt. The portrait uses stylized 2D illustrations rather than a 3D head or lip sync.
- songHeroCar.ts: original 1980s compact sedan, longitudinal 3D body rings, cabin geometry, perspective projection, depth-sorted polygon faces, wheels and rotating spokes, material gradients, glass, lamps and shadow. This is a real 3D vertex model rendered in Canvas, not a loaded GLB, WebGL or photorealistic ray-traced renderer. Painter sorting has limitations at extreme angles.
- New exterior tracking insert at 13.15–15.55 seconds within the existing Freedom shot. The final car recedes along the road and turns toward a straight rear view. The Studio car-angle control selects auto, rear, side or front for drive/road/night shots; the pilot uses the director's automatic angles.
- The thumbnail SVG is an independent composition using the same subject and perspective; the 0.85-second video cover and PNG share the actual Canvas renderer.

No external asset, dependency, workflow or audio generator changes. Inspect the exterior shot, wheels, facial angles, light and cover in Studio and in an actual MP4 before approving. Static checks do not replace browser rendering.

## Preview stability hotfix

The CanvasPreview previously drew once in the animation loop and again after each React time update, and re-subscribed to media/map events on every timestamp. The hotfix separates paused scrubbing from playback, keeps subscriptions stable, limits cinematic interactive preview to 30 fps (offline export is unchanged), and stops playback/audio with a visible error if frame rendering throws. Hero-rig projects open paused. Cinematic grain uses two reusable paths; static face and scene paths have bounded caches. The sedan reuses fixed wheel geometry and only computes rotating spokes each frame. These changes do not replace the 3D model or change scene timing, audio or captions. No new dependencies or CI jobs.

A mock Canvas regression check sampled 100 frames across both episodes, including covers, car insert boundaries and endings. All coordinate and gradient arguments were finite; save/restore stacks were balanced. This is not a native browser/GPU test. The actual mobile Safari tab crash was not reproduced in the development environment; confirm on the affected device after the normal Pages deploy.

## WebKit Canvas compatibility hotfix

The reported iOS frame-001 error was `Not enough arguments`. The earlier performance fix prevents repeated frame rendering but did not eliminate this browser exception. Fast Car now uses a bounded parser for its existing SVG path commands, explicitly traces native Canvas path primitives and draws ellipses with cubic Bézier segments, avoiding Path2D fill/clip/stroke overloads and ellipse overloads. Grain uses one cached bitmap with a native path fallback, and errors now identify the failing cover/scene stage. No changes to the story, 3D car model, export frame rate or audio.

The strict mock regression sampled 100 frames with minimum argument counts and finite coordinate checks. Run `npx tsx scripts/check-song-canvas.ts` manually for future revisions; no new CI workflow. Native iOS WebKit has not been tested, so the exact browser-specific exception remains unconfirmed until device validation.
