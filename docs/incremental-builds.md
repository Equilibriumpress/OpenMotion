# Incremental OpenMotion publications

Pages publishes the full Studio and project library after a merge to main, not MP4 masters. The manual master workflow restores the same media cache and requires FFmpeg explicitly.

The workflow caches npm and pip downloads, Piper model files and generated media. Each project and media family has an independent SHA-256 key containing the producer, cache helper, relevant inputs and expected output paths. Restore verifies every output checksum before copying it into public/. A cache miss regenerates only the affected media group. A cache eviction or first run is a normal cold build. Audio keys include narration, chapter boundaries, durations and voice/effect selection, not visual layout. Runtime mixing settings do not change synthesized files. Travel keys include the source manifest and thumbnail text. Terrain keys include contour configuration. Cat photos and per-episode soundtracks have separate keys.

Cache snapshots use unique run keys and a common restore prefix, since Actions caches are immutable. Pages saves a new snapshot only when media was regenerated. The manual render workflow restores but does not publish cache snapshots. Old snapshots expire under GitHub's cache policy. The cache is an optimization, not the sole source of truth. No generated media or model files are committed. A failed required generator blocks publication; optional geographic contours retain their existing fallback behavior. Dutch fallback narration is not cached as neural narration. Credits and travel atlases are restored together. A valid cache is reused until inputs change; to refresh upstream source media or speech models, delete the relevant Actions cache or change its version.

Logs include HIT/MISS/BUILT per media group and build-timing per stage. The first run populates the cache; subsequent timings depend on cache availability, size, network, and GitHub scheduling. New pushes supersede older Pages runs. No extra test workflow is introduced.
